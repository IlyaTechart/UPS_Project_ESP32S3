# 🔌 USB-to-SPI Data Bridge & Logger для ESP32-S3

[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](https://opensource.org/licenses/MIT)
[![Platform: ESP32-S3](https://img.shields.io/badge/Platform-ESP32--S3-blue.svg)](https://www.espressif.com/en/products/socs/esp32-s3)
[![Framework: ESP-IDF](https://img.shields.io/badge/Framework-ESP--IDF-red.svg)](https://docs.espressif.com/projects/esp-idf/en/latest/esp32s3/)

**Проект ESP32-S3, реализующий высокоскоростной USB-мост для передачи данных между хост-компьютером и внешним устройством по протоколу SPI. Включает в себя тестовый генератор данных на STM32 и инструмент для анализа дампов на ПК.**

---

## 📌 О проекте

Этот проект представляет собой готовое решение для сбора, буферизации и передачи данных по цепочке `Внешнее устройство (FPGA/STM32) ↔️ ESP32-S3 ↔️ USB ↔️ ПК`. В основе ESP32-S3 лежит модифицированная версия официального **ESP USB Bridge** от Espressif, что обеспечивает надежную и быструю работу.

**Ключевая идея:** Создать универсальный "мост" для отладки и взаимодействия с пользовательскими FPGA-модулями через USB без необходимости писать сложные драйверы на стороне ПК.

## 🏗️ Архитектура проекта

Проект состоит из трех независимых частей, каждая из которых находится в своей директории:
UPS_Project_ESP32S3/
├── Loger_Programmer_ESP32/ # Основная прошивка для ESP32-S3 (USB-SPI Bridge)
├── SPI_Master_L152/ # Тестовый генератор данных на STM32 (временная замена FPGA)
└── Dump_analiz_skript/ # Python-скрипт для анализа и сохранения полученных данных на ПК


### 1. 🧠 ESP32-S3 (`Loger_Programmer_ESP32`)
Центральный элемент системы. Прошивка на **ESP-IDF**, реализующая:
*   **SPI Slave**: Прием потока данных от внешнего устройства (STM32 / FPGA).
*   **USB Composite Device**: Эмуляция комплексного USB-устройства для связи с ПК.
*   **Поддержка bridge-режимов**:
    *   `Serial Bridge (CDC)`: Виртуальный COM-порт для передачи данных.
    *   `JTAG/SWD Bridge`: Отладка подключенных MCU через USB.
    *   `Mass Storage Device`: Эмуляция флешки для обновления прошивок.
*   **Обработка кадров**: Парсинг данных по заданной структуре (`frames_structure.h`).

### 2. ⚙️ STM32 (`SPI_Master_L152`)
Временный тестовый стенд, который имитирует работу конечного устройства (будущей FPGA). Генерирует тестовые данные и отправляет их в ESP32 по протоколу **SPI**.

*Этот компонент позволяет отлаживать и валидировать работу ESP32-моста без наличия реального целевого устройства.*

### 3. 🖥️ Хост-ПК (`Dump_analiz_skript`)
Скрипт для автоматизации анализа полученных данных. Запускается на компьютере, читает дампы с USB (полученные от ESP32) и проводит их структурный анализ.

## ✨ Ключевые особенности

*   **Готовая bridge-архитектура**: Использование официального решения от Espressif для надежности и производительности.
*   **Модульность**: Все три компонента системы (ESP32, STM32, ПК) разработаны независимо и легко заменяются.
*   **Протокол SPI**: Обеспечивает высокую скорость обмена данными между устройствами.
*   **Удобство отладки**: Возможность тестировать ESP32-мост с помощью простого STM32-генератора, имитируя реальную нагрузку.
*   **Структурированные данные**: Наличие `frames_structure.h` обеспечивает четкий контракт обмена данными между всеми звеньями системы.

🔄 Схема работы системы
STM32 (или FPGA) генерирует пакет данных и отправляет его в ESP32 через шину SPI.

ESP32-S3, работая в режиме bridge, принимает этот пакет, буферизирует его.

Через интерфейс USB (CDC) ESP32 передает накопленные данные на подключенный ПК.

На ПК запускается Python-скрипт, который читает данные из виртуального COM-порта, парсит их согласно frames_structure.h и сохраняет в читаемом виде для дальнейшего анализа.

🧩 Структура кадра данных (frames_structure.h)
Этот заголовочный файл критически важен для всей системы. Он описывает единый формат данных, который ожидает ESP32 от STM32/FPGA и который, в свою очередь, распознает скрипт на ПК.

SPI_Master_L152 формирует данные в этом формате.

Loger_Programmer_ESP32 использует эту структуру для парсинга принятых данных.

Dump_analiz_skript использует её для интерпретации и визуализации результатов.

Рекомендуется держать этот файл в актуальном состоянии и синхронизировать между всеми тремя компонентами проекта.
